# 个人知识管理系统部署与运行指南

版本：1.0.1  
更新日期：2026-08-12

本文档只说明系统环境、安装、配置、运行、部署和日常维护方式，不包含测试结果、测试账号、论文个人信息或业务数据。

## 1. 系统组成

系统采用前后端分离的 B/S 架构：

- 后端：Java 8、Spring Boot 2.7.18、Spring Security、JWT、MyBatis-Plus 3.5.4
- 前端：Vue 3.3.8、Vue Router、Pinia、Axios、Element Plus、Vite 5.0.4
- 数据库：MySQL 5.7 或更高版本，数据库名为 `knowledge_db`
- 后端默认端口：`8088`
- 前端开发端口：`5173`
- 接口前缀：`/api`

项目目录如下：

```text
gggrrrzzzsss/
├─ backend/                 Spring Boot 后端
├─ frontend/                Vue 前端
├─ database/init.sql        数据库结构初始化脚本
├─ docs/                    系统文档
├─ README.md
└─ CHANGELOG.md
```

## 2. 环境要求

本地或服务器需要准备：

- JDK 8
- Maven 3.6 或更高版本
- Node.js 18 或 20 及更高兼容版本
- npm（随 Node.js 安装）
- MySQL 5.7 或更高版本
- Chrome、Edge 或其他现代浏览器
- 生产环境可选：Nginx、systemd

可以先检查环境：

```bash
java -version
mvn -version
node -v
npm -v
mysql --version
```

## 3. 初始化数据库

1. 启动 MySQL 服务。
2. 登录 MySQL：

   ```bash
   mysql -u root -p
   ```

3. 在 MySQL 客户端中执行初始化脚本。Windows 路径建议使用正斜杠：

   ```sql
   SOURCE C:/你的项目路径/gggrrrzzzsss/database/init.sql;
   ```

   Linux 或 macOS 也可以在项目根目录执行：

   ```bash
   mysql -u root -p < database/init.sql
   ```

4. 确认数据库已创建：

   ```sql
   USE knowledge_db;
   SHOW TABLES;
   ```

初始化脚本只创建数据库和表结构，不写入测试账号、示例笔记或个人数据。

## 4. 配置运行环境变量

后端启动前必须设置数据库密码和 JWT 密钥。初次部署还应设置初始管理员密码。不要把真实值写进源码、提交到 Git，或粘贴到公开日志中。

### 4.1 Windows PowerShell

在将要启动后端的同一个 PowerShell 窗口中执行：

```powershell
$env:DB_URL = "jdbc:mysql://localhost:3306/knowledge_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false"
$env:DB_USERNAME = "root"
$env:DB_PASSWORD = "<你的数据库密码>"
$env:JWT_SECRET = "<至少32位的随机密钥>"
$env:JWT_EXPIRATION = "86400000"
$env:INITIAL_ADMIN_USERNAME = "admin"
$env:INITIAL_ADMIN_PASSWORD = "<初始管理员强密码>"
$env:INITIAL_ADMIN_NICKNAME = "管理员"
```

这些变量只对当前 PowerShell 会话生效，关闭窗口后需要重新设置。

### 4.2 Linux 或 macOS

```bash
export DB_URL='jdbc:mysql://localhost:3306/knowledge_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false'
export DB_USERNAME='root'
export DB_PASSWORD='<你的数据库密码>'
export JWT_SECRET='<至少32位的随机密钥>'
export JWT_EXPIRATION='86400000'
export INITIAL_ADMIN_USERNAME='admin'
export INITIAL_ADMIN_PASSWORD='<初始管理员强密码>'
export INITIAL_ADMIN_NICKNAME='管理员'
```

可选变量：

- `SERVER_PORT`：后端端口，默认 `8088`
- `DB_URL`：完整 JDBC 地址，默认连接本机 `knowledge_db`
- `DB_USERNAME`：数据库用户名，默认 `root`
- `JWT_EXPIRATION`：Token 有效期，默认 `86400000` 毫秒（24 小时）
- `INITIAL_ADMIN_USERNAME`：初始管理员用户名，默认 `admin`
- `INITIAL_ADMIN_NICKNAME`：初始管理员显示名称，默认 `管理员`

如果没有设置 `INITIAL_ADMIN_PASSWORD`，后端会跳过初始管理员创建。管理员已存在时，后续启动不会重复创建或覆盖密码。

## 5. 本地开发运行

建议按“数据库 → 后端 → 前端”的顺序启动。

### 5.1 启动后端

进入后端目录：

```bash
cd backend
mvn clean package
java -jar target/knowledge-backend-1.0.1.jar
```

开发时也可以直接运行：

```bash
mvn spring-boot:run
```

看到 Spring Boot 启动完成日志后，后端地址为：

```text
http://localhost:8088
```

### 5.2 启动前端

另开一个终端，进入前端目录：

```bash
cd frontend
npm ci
npm run dev
```

浏览器访问：

```text
http://localhost:5173
```

开发服务器会把 `/api` 请求代理到 `http://localhost:8088`。如果修改了后端端口，需要同步修改 `frontend/vite.config.js` 中的代理目标后重启前端。

### 5.3 停止系统

前端或后端在当前终端前台运行时，按 `Ctrl+C` 停止。MySQL 可按操作系统的服务管理方式停止；如果机器还运行其他系统，不要仅为停止本项目而关闭共享数据库服务。

## 6. 生产环境部署

以下示例以 Linux、Nginx 和 systemd 为例。

### 6.1 构建后端

```bash
cd backend
mvn clean package
```

构建产物：

```text
backend/target/knowledge-backend-1.0.1.jar
```

将 JAR 放到服务器，例如：

```text
/opt/knowledge/knowledge-backend-1.0.1.jar
```

### 6.2 构建前端

```bash
cd frontend
npm ci
npm run build
```

构建产物位于 `frontend/dist/`。将其中内容复制到服务器静态目录，例如：

```text
/var/www/knowledge/
```

### 6.3 使用 systemd 运行后端

创建仅 root 可读的环境文件 `/etc/knowledge/knowledge.env`：

```ini
DB_URL=jdbc:mysql://127.0.0.1:3306/knowledge_db?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false
DB_USERNAME=<数据库用户名>
DB_PASSWORD=<数据库密码>
JWT_SECRET=<至少32位的随机密钥>
JWT_EXPIRATION=86400000
INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=<初始管理员强密码>
INITIAL_ADMIN_NICKNAME=管理员
SERVER_PORT=8088
```

限制环境文件权限：

```bash
sudo chmod 600 /etc/knowledge/knowledge.env
```

创建 `/etc/systemd/system/knowledge.service`：

```ini
[Unit]
Description=Knowledge Management Backend
After=network.target mysql.service

[Service]
Type=simple
User=knowledge
WorkingDirectory=/opt/knowledge
EnvironmentFile=/etc/knowledge/knowledge.env
ExecStart=/usr/bin/java -jar /opt/knowledge/knowledge-backend-1.0.1.jar
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动并设置开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now knowledge
sudo systemctl status knowledge
```

查看日志：

```bash
sudo journalctl -u knowledge -f
```

### 6.4 配置 Nginx

示例站点配置：

```nginx
server {
    listen 80;
    server_name example.com;

    root /var/www/knowledge;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

`proxy_pass` 地址末尾不要再添加 `/`，否则可能去掉原请求中的 `/api` 前缀。

检查并重新加载 Nginx：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

生产环境建议为域名配置 HTTPS，并只向公网开放 80/443 端口；MySQL 和后端 8088 端口仅允许本机或受控内网访问。

## 7. 更新与回滚

更新时建议先备份数据库，再替换 JAR 和前端静态文件：

```bash
mysqldump -u <数据库用户名> -p knowledge_db > knowledge_db_backup.sql
sudo systemctl stop knowledge
# 替换后端 JAR 与前端 dist 文件
sudo systemctl start knowledge
sudo systemctl status knowledge
```

若新版本异常，可恢复上一版 JAR、上一版静态文件和必要的数据库备份，然后重新启动服务。不要在未备份时直接覆盖数据库。

## 8. 常见问题

### 后端提示数据库连接失败

- 确认 MySQL 已启动。
- 确认 `knowledge_db` 已初始化。
- 检查 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`。
- 确认数据库用户有访问 `knowledge_db` 的权限。

### 后端提示缺少配置项

`DB_PASSWORD` 和 `JWT_SECRET` 没有源码默认值，必须在启动后端的同一环境中设置。systemd 部署时检查 `EnvironmentFile` 路径和文件权限。

### 前端能打开但接口请求失败

- 本地开发时确认后端监听 `8088`。
- 确认 Vite 代理目标和实际后端端口一致。
- 生产环境检查 Nginx `/api/` 反向代理及后端服务状态。

### 页面刷新后出现 404

Vue 使用前端路由，Nginx 必须包含：

```nginx
try_files $uri $uri/ /index.html;
```

### 登录后很快失效

检查服务器时间是否正确，以及 `JWT_EXPIRATION` 是否设置为预期毫秒数。多实例部署时所有后端实例必须使用同一个 `JWT_SECRET`。

### 端口被占用

修改 `SERVER_PORT` 后，还要同步修改 Vite 开发代理或 Nginx 反向代理的目标端口。

## 9. 安全注意事项

- 不要将数据库密码、JWT 密钥、管理员密码或 `.env` 文件提交到 GitHub。
- 初始管理员创建后，应妥善保管密码；发生泄露时立即修改密码并轮换 JWT 密钥。
- 生产环境使用独立的低权限数据库账号，不建议长期使用 MySQL `root`。
- 定期备份数据库，并验证备份可以恢复。
- 配置 HTTPS、防火墙和最小端口开放策略。
- 只发布 `database/init.sql` 表结构脚本，不发布本地演示数据、运行日志或数据库快照。
